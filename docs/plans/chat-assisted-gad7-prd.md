# 聊天辅助 GAD-7 测评 PRD（后端首版）

## 目标与范围

面向不愿逐题填写量表的成年用户，把 GAD-7 的七个维度转为自然聊天话题。用户主动开始一段引导对话，系统从回答中提取候选，一次回答可覆盖多个维度，只对仍不明确的维度自然过渡。结束时集中核对一次并提交，保留量表的自评性质。首版仅支持 GAD-7、中文、用户主动发起；PHQ-9、ISI 和聊天中自动弹出邀请留待验证后扩展。

## 核心原则

- 聊天线索不是量表答案。模型只提出候选值，不计算或保存正式分数。
- 只读取当前认证用户选定会话中近 14 天的用户消息，不读取机器人回复，不跨用户取数。
- 未提及、时间窗不清、频率不清或自相矛盾的项目一律为未知，不以 0 补齐。
- 对话中使用生活化话题和一次一个开放式问题，不逐字朗读量表题干或选项；一次回答可以提供多个维度的候选。每个维度最多引导两次，避免反复追问。
- 用户开始时明确以“过去两周”为范围。结束时集中核对七个候选，缺失项由用户补充；只有用户最终提交的七个值才进入原有确定性计分与解释逻辑。
- 草稿与正式量表分开保存。正式记录标记 `chat_assisted`，草稿保留来源消息 ID、模型候选和用户确认记录以供本人回看和删除。
- 草稿在 24 小时后不能继续引导或提交；重新开始时再确认新的“过去两周”时间窗。
- 不因本功能改变现有对话风险分类与危机处置；若当前用户消息有风险，仍由原对话安全流程先处理。

## 用户故事

1. 用户主动选择“聊一聊最近的状态”，阅读须知并确认使用本段聊天内容和“过去两周”的时间范围。
2. 系统从已有聊天线索选择第一个未覆盖的话题，用自然语言引导。用户可以自由表达；一次回答可涵盖多个维度。
3. 每轮先处理风险信号，再提取候选并给出简短共情回应与下一个话题；含糊回答最多澄清一次，然后允许跳过。
4. 聊完后展示一次总览：七个维度的拟填值、证据或“尚不清楚”。用户集中修订或补齐并提交；未提交草稿不进正式趋势。
5. 用户可随时退出；清空记录或注销账号会删除草稿和正式记录。

## 后端接口

- `POST /v1/assessments/chat-assisted/drafts`：传 `user_id`、`session_id`、`consent_acknowledged=true`，生成草稿；只使用该用户近 14 天的聊天消息。
- `GET /v1/assessments/chat-assisted/drafts/{draft_id}`：读取本人草稿和逐题状态。
- `POST /v1/assessments/chat-assisted/drafts/{draft_id}/turns`：提交一轮自由回答；返回自然引导或风险暂停消息、下一个话题与草稿状态。
- `POST /v1/assessments/chat-assisted/drafts/{draft_id}/review`：一次提交七个用户核对后的值，并显式确认已核对和过去两周时间窗；原子保存正式结果，重复请求不生成重复记录。
- 原逐题确认和完成接口保留为兼容/手动补录路径，客户端主路径使用对话与集中核对。

## 数据与质量

草稿保存 `user_id`、会话 ID、量表代码、模型候选 JSON、已引导次数、已确认答案 JSON、状态、时间与最终测评记录 ID。引导轮次写入原会话消息；候选证据只存消息 ID，不在草稿中复制聊天原文。模型输出需校验题号、值域、证据归属；模型不可用时暂停引导，用户仍可在最终核对中手动补齐。高风险表达中断测评话题并给出危机回复，不提取候选。

验收场景：跨用户访问被拒绝；无证据不会生成 0；一次回答可覆盖多个维度；含糊回答不会无限追问；高风险回答中断引导；模型候选不能直接计分；最终七个值均由用户提交；重复完成不会重复计分；清空/注销会删除草稿。上线前由心理专业人员复核中文引导语、量表措辞、解释、同意文案及标注样本，比较候选准确率与传统逐题流程完成率。

## 非目标

首版不提供被动长期监测、后台自动打分、诊断、PHQ-9 第 9 题自动填写、付费墙或客户端交互。
